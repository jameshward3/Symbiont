# Project Controls

## Authorization gate

Do not classify a project Active until one source is linked: executed agreement, approved internal authorization, or explicit documented pre-contract authorization. Record project ID/name, client/stakeholders, authorization reference, scope/exclusions, deliverables/acceptance, budget/commercial model, dates, project manager/accountable owner, team, communication cadence, approved systems, and data classification. Unknown information stays `Unknown` and receives an owned, dated resolution action.

## Controlled setup

Create a charter, scope baseline, deliverable register, milestone schedule, responsibility matrix, communication plan, action register, risk/issue register, decision register, change register, quality plan, document-control rules, and closeout checklist. Use `PRJ-YYYY-NNN`; `DEL`, `MIL`, `ACT`, `RSK`, `ISS`, `EXC`, `DEC`, `CHG`, `QA`, `RPT`, `EV`, and `CLS` prefixes with year and sequence for child records.

Every governed record includes stable ID, project ID, shared goal ID, correlation ID, accountable owner, status, created/updated timestamps, and source evidence. Names are not relational keys. Preserve source versions and append material events rather than silently overwriting history.

## Monitoring and status

Review milestones, overdue actions, deliverables, dependencies, blocked work, scope/schedule variance, forecast effort/margin signals, quality, client decisions, missing information, approvals, and change exposure. Status reports lead with exceptions, decisions, and required action; include overall health, milestone progress, completed outcomes, next gates, overdue work, risks/issues, change exposure, financial warnings, quality, client communication required, and owner/date for every action.

Client-facing reports remain drafts until an authorized human approves sending. Financial systems remain authoritative for actual budget, invoice, and margin data.
